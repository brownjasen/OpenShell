# 字体与工作台外观修复

日期：2026-10-16

本轮依据用户提供的隧道表格与主机侧栏截图修复显示问题。没有连接用户服务器，没有读取或修改用户保存的主机数据。修改前源码和 JAR 位于工作区 `.work2/ui-repair-before-20261016/`。

## 原因

- 隧道表格强制使用物理字体 Consolas，缺少中文字形。修复前测试在“远程 MySQL 穿透”的第一个汉字处即检测到无法显示；这是字体缺字，不是 SSH 编码错误。
- 界面混用了 FlatDarkLaf 默认面板背景与自定义深色背景，导致工具栏、标签区出现厚重的灰色块。
- 主机树行选中背景来自 FlatLaf，嵌套渲染面板又画了另一种颜色，形成用户截图中的拼接选中块。修复前回归测试复现了两者颜色不同。
- 菜单使用主题默认字体，其他控件又各自硬编码字体与尺寸；部分自定义组件不随 FlatLaf 用户缩放同步变化。固定的文件区最小高度无法保证缩放后仍有文件行。

## 修改

- 新增统一的 FlatLaf 应用主题资源，覆盖深色和浅色的面板、菜单、工具栏、输入框、标签与选中背景。启动、主题切换及渲染验证使用同一入口。
- Windows 界面优先使用 Microsoft YaHei UI / Microsoft YaHei，并提供逻辑字体回退；中文名称和说明使用界面字体，地址、代码和终端使用具备回退能力的逻辑等宽字体。
- 字号、矢量图标、文件行高和终端字体随 FlatLaf 用户缩放变化；保存的终端字号仍是逻辑字号。
- 工具栏改为较轻的按钮和统一的矢量图标；去掉操作标签中的 Emoji。侧栏简化为“连接”标题与图标按钮，保留双行主机信息。
- 主机渲染面板使用透明绘制，采用整行一致的选中颜色；修复浅色主题下会话标题仍保留深色文字设置的问题。
- 隧道表格中文正常显示，地址保留等宽排版，长说明可悬停查看。新建、编辑、启动、停止、删除行为保持原逻辑。
- 监控收为紧凑状态条，保留 CPU、内存、根分区、网络速率和宽窗口下的历史波形；窄窗口按空间收起部分信息。不可用状态显示横线与状态文字，不填充假采样。
- 文件区根据工具栏、表头、状态栏及两行文件的实际高度计算最小空间。小窗口临时限制分屏位置，不把该限制覆盖保存的比例；空间恢复后使用原比例。
- 联调暴露监控 exec 通道会关闭应用的 System.err。新增失败回归断言后，改用 JSch 的不关闭外部流参数，避免后续异常被吞掉。没有更改监控命令或采样口径。

## 验证与边界

- 普通 `mvn -B -ntp clean verify` 成功：31 项测试，失败、错误和跳过均为 0。
- 本轮新增四项显示回归：隧道中文的真实渲染字体具备字形、主机选中背景一致、深浅主题表面与字体一致、紧凑网络图仍保留垂直绘图空间。
- 原监控 EOF 集成测试增加 System.err 不被关闭的断言；修复前失败，修复后通过。
- 150% FlatLaf 用户缩放、非 headless 环境下定向复核会话、工作区、SSH 和显示回归，共 12 项通过。
- 使用最终可执行 JAR 置于类路径首位，移除 target/classes，结合测试用的回环 SSH/SFTP 服务创建完整主窗口、创建原生窗口句柄并渲染。普通缩放、150% 用户缩放及请求 1920×1080 的宽窗口预览均输出 `WORKBENCH_APPEARANCE_PREVIEW_OK`。
- 检查了深浅主题整窗、侧栏选中行、文件与隧道表格的渲染图片。最终 JAR 内三个主题资源均存在。
- 图片来自未显示的真实 Swing 组件及隔离测试连接，不是设计稿；测试服务不提供 Linux 监控命令，图片中的监控不可用为预期。没有进行桌面逐项点击、真实 Windows DPI/多显示器或用户服务器验收。

构建与预览日志中的 Unknown command 来自隔离服务对 Linux 监控命令的预期拒绝，关闭连接可能出现服务端连接重置警告。原有 Shade 资源重叠警告仍存在，不将它们计为本轮测试失败。
