# OpenShell 下一步制作与优化路线

日期：2026-10-16

执行进度：第一批连接与终端基础、第二批工作区持久化/命令历史/嵌套分组已落地。真实 Linux 交互、自动目录跟随和 M3–M5 尚待完成。详见 [第一批记录](m1-implementation-2026-10-16.md) 与 [第二批记录](m2-implementation-2026-10-16.md)。

本文件保留最初规划与基线分析，当前进度以上方状态和实施记录为准。规划依据最初 OpenShell 源码、抽读的 FinalShell 反编译代码及官方公开资料形成。用户后续已授权分批实施；此文不包含提交或发布安排。现已完成隔离 SSH/SFTP 集成、组件渲染和打包构造检查，真实 Linux 桌面交互与性能仍待验证。

## 1. 产品目标与判断

建议先把 OpenShell 做成适合每天使用的 Windows SSH/SFTP 桌面工作台，继续使用 Swing/FlatLaf 和 JSch。后续再根据需求扩展平台与高级功能。

用户说的“FinalShell 那股味道”，可以转成四个设计目标：

1. **工作区集中**：服务器、终端、命令输入、文件和状态都围绕当前会话组织，常用操作不必频繁切换页面。
2. **终端行为正确**：光标、颜色、回显、窗口尺寸、中文和全屏程序表现符合远程程序预期。
3. **文件与命令连贯**：找到目录、复制路径、执行命令、编辑文件、上传结果有连续反馈。
4. **长期操作可靠**：大文件传输不阻塞浏览，网络中断有明确状态，重新连接、关闭和保存不会留下不确定结果。

从布局代码推断，当前界面有较多工具栏、长文字按钮、Emoji、卡片和重复标题，操作入口较多。建议逐步转为更紧凑、以工作内容为中心的桌面工具布局。实际密度与间距需要运行后判断，不以静态阅读代替视觉验证。

## 3. 路线和依赖

按 M1 → M2 → M3 → M4 → M5 推进。M1 先解决基础行为；M2 建立日常工作台；M3 补足文件操作；M4 完善运维信息；M5 扩展连接和交付。不要以页面数量作为阶段完成标准。

### M1：可信赖的连接与终端

**目标：连接后可以正常执行交互操作，连接失败、断线、关闭均有准确反馈。**

实施顺序：

1. 建立可重复的构建和最小测试环境，确认当前 JAR 能构建、启动；登记已有问题。
2. 对 JediTerm 做一个最小接入验证：JSch Shell 输入输出 → 终端连接适配 → Swing 终端组件。核对所选版本的 JDK、Maven 依赖和打包兼容性，通过后锁定版本。
3. 替换 JTextArea 终端输出区；保留已有单行/多行命令编辑器。交互输出交给终端组件解释，停止用正则删除控制序列。
4. 接通行列数变化与 resizePty；使用连续字符解码，处理字符和控制序列跨网络读取边界的情况。
5. 建立连接状态：未连接、连接中、已连接、重连中、已断开、失败、已关闭。会话数量与连接徽标由真实状态驱动。
6. 支持取消连接；每次连接使用独立代次标识，关闭或重连后丢弃旧连接的回调，失败时回收已建立的通道。
7. 最小可靠性与安全准备：主机指纹首次确认、known_hosts 保存、指纹变化明确阻止静默接受；配置写入采用临时文件替换和错误反馈。
8. 暂时隐藏或标为未实现的 SOCKS5 入口，避免把固定转发显示成动态代理成功。

相关现有文件：pom.xml、ssh/SshSession.java、ui/TerminalPanel.java、ui/SessionPanel.java、ui/MainWindow.java、storage/HostStorage.java、ui/PortForwardPanel.java。

建议新增小模块：terminal/SshTtyConnector、session/SessionController、session/SessionState。仅按职责拆分，不引入大型框架。

验收：

- 在真实或隔离测试 SSH 服务中运行 bash、vim、top、less；退出后屏幕与提示符正常。
- 彩色输出、光标移动、中文、Tab、方向键、Ctrl+C、复制粘贴和多行粘贴符合设定。
- 拖动窗口及分割线后远端 stty size 与终端行列一致。
- 连接中关闭标签不会稍后出现已关闭会话；重连不会重复启动读线程和监控。
- 认证失败、远端关闭和网络中断能区分显示；关闭后通道和后台任务结束。
- 首次指纹确认、再次连接及指纹变化均经过验证。

### M2：紧凑、连续的工作台

第二批已实施：工作区与文件视图设置保存、可搜索命令历史/前缀补全/自定义命令、嵌套分组/移动/最近连接、紧凑首页与文件工具栏、显式 cd 草稿保护。自动目录跟随、远程路径补全、全套图标统一与真实桌面/DPI 操作验收仍待后续，不将本阶段标记为全部完成。

**目标：打开会话后，终端始终是主角，命令输入与文件操作随手可用。**

建议布局：

```text
菜单 / 紧凑工具栏
┌──────────┬─────────────────────────────────────┐
│ 主机树   │ 服务器 A | 服务器 B | 编辑文件       │
│ 搜索     ├────────┬────────────────────────────┤
│ 分组     │ 会话   │ 终端                       │
│ 最近连接 │ 指标   │                            │
│          │ 可折叠 ├────────────────────────────┤
│          │        │ 单行命令 / 可展开多行编辑  │
│          ├────────┴────────────────────────────┤
│          │ 文件 | 传输 | 进程 | 端口           │
│          │ 路径栏 + 目录树/文件表              │
└──────────┴─────────────────────────────────────┘
状态栏：连接状态 / 后台任务 / 必要的会话信息
```

这是建议原型，实施前应以当前窗口实测可用空间；监控放侧栏还是紧凑顶栏，可用同一功能做比较后确定。

工作项：

- 减少层层工具栏和重复的主机地址、功能标题；低频操作移入菜单或右键菜单。
- 统一矢量图标、字体、行高、间距、选中态和禁用态。Emoji 不再承担核心状态图标职责。
- 提供分屏、专注终端、专注文件三种布局，保存分割比例、侧栏开关、表格列宽与字体设置。
- 欢迎页保留快速连接与最近主机，首次连接后优先展示工作区。
- 统一快捷键并实际绑定 Action/InputMap；菜单文字标注快捷键不能代替绑定。
- 区分复制和向远端发送 Ctrl+C；滚动查看历史时不强制跳回底部；提供回到底部入口。
- 实现主机分组的增删改、嵌套、拖动移动，以及最近连接记录。
- 保存和搜索命令历史；支持用户自定义快捷命令。补全先做本地历史与明确触发的远程路径查询。

目录联动按两步实施：

1. 可靠的显式操作：“在终端进入此目录”“复制文件路径”“文件面板进入当前终端目录”。发送 cd 前确认终端空闲，用户输入未发送内容时不抢占输入。
2. 再增加可选 shell 集成，跟随真实目录变化；不把任意提示符正则匹配或另开 exec 执行 pwd 当成当前交互 Shell 目录。支持不了的 Shell 明确降级到显式操作，不擅自修改远端启动文件。

相关文件：ui/MainWindow.java、ui/SessionPanel.java、ui/HostTreePanel.java、ui/ThemeUtils.java、ui/TerminalPanel.java、ui/SftpPanel.java。

验收：在 1366×768、1920×1080，以及 100%/150% 缩放下检查按钮截断、终端行数和文件可见空间；连续完成“连接 → 进入目录 → 执行命令 → 找文件 → 打开编辑”的工作流；重启后布局可恢复。比较前后截图与操作步骤，而非只判断配色相似。

### M3：可靠的文件工作流

**目标：传输大文件时仍可浏览目录，编辑和保存有可恢复结果。**

先修正确性：

- 当前 loadTreeSubDirsAsync 调用 SftpClient.listFiles，而 listFiles 会 cd 并修改共享 currentPath；上传下载又使用相对文件名。先把目录浏览、UI 当前目录和操作目标解耦。
- 所有操作提交时保存绝对路径与所选项目快照；后台运行不再读取可能变化的当前目录或选中行。
- 目录加载带请求序号，快速切换时旧结果不能覆盖新目录；树展开不改变文件表的操作目标。
- 浏览和传输分开使用 SFTP 通道，限制传输并发。JSch Session 是否需要额外拆分，以真实传输与交互延迟结果决定。
- 统一远端 Shell 参数转义；压缩解压命令中的特殊文件名不能改变命令含义。

再补能力：

- 文件多选、批量操作、本地文件/目录拖入上传、递归上传下载。
- 传输列表记录路径、方向、总量、已传、速度、状态、错误；支持取消、失败重试和批量冲突策略。
- 优先完成可靠重试，再实现断点续传；续传前核对远端和本地文件是否仍符合前提。
- 保存上传路径快照、显示隐藏文件、数字大小排序、目录懒加载与有失效规则的缓存。
- 在线编辑增加语法高亮、搜索替换、修改标记、保存/放弃/取消关闭，以及加载失败时禁止误保存。
- 保存时在 UI 线程取得文本快照；上传失败保留本地副本和未保存状态。成功用状态栏提示，避免每次保存弹窗。
- 保存前核对远端大小/时间等变化，发现变化给出冲突处理；临时文件上传后重命名保存，核对服务器支持、权限、符号链接和元数据行为，不能保证时明确采用的保存策略。
- 明确文本大小、编码与二进制文件边界；避免一次性打开任意大文件。

相关文件：ssh/SftpClient.java、ui/SftpPanel.java、ui/RemoteEditorPanel.java、ui/MainWindow.java。建议拆出 TransferService/TransferTask、RemoteFileService 和编辑文档状态，避免继续把任务逻辑堆入面板。

验收：传输期间切目录、展开树和打开编辑；中文/空格/引号/美元符号文件名；大文件和多层目录；取消、断网、磁盘不足、权限拒绝与同名覆盖；文件校验值一致；远端被其他程序修改后不静默覆盖。

### M4：有解释力的运维监控

**目标：指标能支持判断问题，采集失败可见。**

- CPU、内存和网络历史图；网卡选择与各接口明细；挂载点列表；系统、内核、运行时间信息。
- 区分正常、采集中、无权限、命令缺失、过期、断开；采集失败不能伪装为 0%。
- 使用稳定的采样时间差，处理计数器回退、接口消失和重连后的基线重置；补充 CPU steal 等指标口径。
- 修正 /proc/net/dev 的解析边界，固定远端输出 locale；对不同命令版本和受限系统做兼容。
- 进程/端口页支持可配置自动刷新、暂停、排序、搜索、详细信息与错误反馈；进程操作先普通终止，需要时再强制终止。
- 活跃页面使用较高刷新频率，后台页面降频或暂停；监控停止不影响交互 Shell。
- 使用有界后台执行器和统一超时/取消机制，UI 更新回 Swing EDT。

相关文件：ssh/ServerMonitor.java、ui/MonitorPanel.java、ui/ProcessManagerPanel.java、ui/PortMonitorPanel.java。

验收：Linux 常见发行版及普通用户权限；命令缺失/输出变化；负载变化与系统工具采样对照；多会话运行时的 CPU、内存、任务数与终端响应。先测量，再为可支持的会话规模制定阈值。

### M5：高级连接与可分发版本

按实际使用需要逐项加入，不要求同一版本全部完成：

- 跳板机、连接代理、保活和可配置重连策略；有活动传输和未保存文档时明确恢复行为。
- 本地/远程转发规则持久化、状态与绑定冲突提示；实现真正的 SOCKS5 协商及按请求目标转发，验证 DNS 行为。
- 凭据与普通主机配置分离。默认导出不包含密码、私钥口令；选择是否保存凭据，明确存储位置。Windows 凭据保护方案另做小规模兼容性验证，不自行设计加密算法。
- 多终端分屏、明确目标列表的广播输入、会话日志等高级操作。
- Windows 安装包与内置运行时、图标、版本信息、配置迁移、脱敏诊断日志、依赖许可证清单。
- 云同步、远程桌面、网络加速、插件市场、AI 助手、ZMODEM 作为后续候选，根据需求和维护成本单独排期。

验收：两跳 SSH 的失败与恢复；本地/远程转发的真实流量；SOCKS 客户端访问不同目标；没有预装 Java 的干净 Windows 环境安装运行；升级后主机和设置仍可用；导出和诊断文件无意外凭据泄露。

## 4. 第一个可交付里程碑

第一轮集中完成以下三件事：

1. 真实终端：vim/top、颜色、中文、窗口缩放和键盘操作通过。
2. 可靠会话：连接中/成功/失败/断开准确，关闭与重连不残留后台任务。
3. 一个紧凑的“终端 + 命令输入 + SFTP”工作台原型，跑通完整文件编辑工作流。

其中 SFTP 的共享目录问题、无效 SOCKS5 入口和基础配置写入可靠性，随第一轮处理；不等到扩展功能阶段再修。

达到这三点后再扩充功能面。每完成一阶段更新能力矩阵，分别记录“已实现”“自动化验证”“桌面验证”“真实 SSH 验证”，不把按钮存在作为通过依据。

## 5. 验证与估算方式

- 规划时没有启动真实服务器或构建安装包；后续实施证据分别保存在每批记录。
- 实施时先运行 `mvn -f OpenShell/pom.xml clean verify`；该命令成功只证明构建与已有测试，不证明桌面或 SSH 行为。
- 自动化优先覆盖状态转换、目录结果去旧、路径转义、解析样本、传输取消/失败和配置原子保存等容易回归的逻辑。
- 组件接入先做最小原型，再拆任务估时；不在缺少构建基线、真实服务环境和人力信息时承诺精确日历工期。
- 保持现有 UI 可分阶段替换；提取后台服务和状态模型，避免一次性重写整个工程。
- FinalShell 反编译代码用于理解行为和流程，OpenShell 的实现采用清晰模块与可维护依赖；不移植其混淆/反射架构。

## 6. 参考依据

本地证据主要来自 `src/main/java/org/openshell/`，以及同级工作区 `code/src/` 下的 st、com/Fv、com/Cn、com/DI、com/Xe、W9、Ww 等类。FinalShell 只做了选择性抽读，未完整审计，不能据此断言两个产品的全部差异。

公开资料核对日期：2026-10-16。

- [FinalShell 官方产品说明](https://www.hostbuf.com/t/988.html)：终端与文件同屏、目录联动、命令辅助输入、无 Agent 监控、编辑器和文件传输等产品方向。用于确定工作流参考，不将所有高级功能列为当前版本必做。
- [FinalShell 官方常见问题](https://www.hostbuf.com/t/1088.html)：监控受权限/系统命令影响、SFTP 与 exec 能力存在环境前提，用于制定失败状态与兼容性验收。
- [JetBrains JediTerm](https://github.com/JetBrains/jediterm)：可嵌入 Java/Swing 的终端组件，支持终端仿真和尺寸变化。作为优先验证方案；具体版本的 JDK 和构建兼容性仍需原型确认。
