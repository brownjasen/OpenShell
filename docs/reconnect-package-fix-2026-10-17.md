# 重连状态与发布包修复验收

日期：2026-10-17。已修复上一轮验收确认的三项缺陷，并完成构建、组件/协议测试与已授权 已授权测试机 实测。修复前证据保留在 [原验收记录](acceptance-2026-10-17.md)，不能把其中旧结论当成当前状态。

## 本轮行为

1. **重连保留未发送草稿。** 单行、多行文本、光标/选择方向、编辑模式、局部发送设置、历史导航与 F6 输入目标通过不可变内存快照恢复。重连失败或取消后再次重试仍保留；不会自动发送、记录为已执行历史或把未发送内容写到配置。新输入优先，拒绝覆盖已有草稿，最终关闭释放快照。
2. **原远程编辑标签恢复保存。** 每个会话持有稳定的编辑器 SFTP 客户端，断线暂停、成功重连后绑定新物理连接。浏览器的旧客户端关闭不再使编辑标签失效。编辑器保留本地修改与原文件版本，离线期间远端有变化时仍提示冲突；`ownsClient` 在断线及重连后保持关联关闭保护。
3. **发布 JAR 恢复 Ed25519。** Shade Manifest 写入 `Multi-Release: true`，让 JDK 使用 JSch 的对应实现；依赖版本不变。实际 fat JAR 在原 OpenShell Ed25519 信任记录下成功连接 已授权测试机，没有关闭指纹校验或接受新的密钥。

编辑器切换连接不会在 EDT 等待网络。每个请求只使用捕获的旧物理客户端，不会自动改用新连接重试；如果操作期间连接已切换，保守报告结果未确认，保留本地内容。会话固定连接目标快照，代理另外校验主机、端口和用户，防止旧编辑器被接到另一台机器。

实现涉及 `SessionPanel`、`TerminalPanel`、新增 `ReconnectingSftpClient` 和 `pom.xml`。没有改用户保存的连接、凭据、主题、指纹库或业务文件，没有提交或推送。

## 测试脚本修正与保留记录

- 新包验签 probe 最初误把原始 64 字节签名交给要求 SSH 格式签名包的 JSch 验签接口，引发越界。修正为算法名与签名两段 SSH string（83 字节），JDK 互验仍用原始签名；签名、验签、篡改拒绝断言保留，正式代码未因此修改。
- 回环服务器 Shell factory 原先把新实例写到共享字段后又返回共享字段，并发会话可能得到同一实例，出现 `IllegalThreadStateException`。改为返回本次创建的局部实例，保留字段仅作观测；失败/取消重试及隔离用例在最终全量通过。
- 一次全量中，存量编辑冲突用例等待 Windows 测试文件内容超过原 8 秒期限，超时栈位于 `Files.readString`。补充失败诊断后，定向 3/3 及最终全量均通过；未放宽期限或改变产品保存逻辑。原因尚未确定，不把该次超时报成已修复的产品缺陷，原日志保留。
