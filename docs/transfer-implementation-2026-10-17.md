# 传输队列、独立通道与覆盖保护

本批范围与顺序见 [实施计划](transfer-plan-2026-10-17.md)。保留工作台布局，在文件操作栏增加“传输”，下方增加传输标签。

## 已实现

- 上传及下载加入当前会话的 FIFO 队列，提交时保存本地和远端绝对路径。批量上传依次执行；每个任务使用新的 SFTP 通道，浏览与编辑沿用独立的浏览通道。任务完成不抢走用户当前标签焦点。
- 传输表显示方向、文件、百分比进度、已传/总字节、平均速度、状态、目标路径及错误详情。取消、从头重试、清理结束项均依据实际任务状态启用；排序后操作仍作用于选中的任务。
- 同名文件提供覆盖、保留两者、跳过和取消任务，可将处理方式应用于本批次。保留两者生成 `文件 (1).扩展名` 等名称。重试创建新任务，从头传输并重新检查冲突。
- 上传先写远端同目录随机 `.openshell-*.part` 文件，核对来源与目标属性后再发布；已有目标的覆盖要求服务端协商 `posix-rename@openssh.com=1`。不支持时失败并保留原目标，不先删除旧文件。已有普通权限位复制到暂存文件，不承诺保留所有者、ACL 或硬链接语义。
- 下载先写本地同目录临时文件，完成后核对远端源和本地目标属性。新目标不允许替换已经出现的本地文件；覆盖已有文件使用文件系统原子移动，不支持时明确失败。
- 取消会关闭本任务的通道并清理临时文件，不关闭浏览通道；等待项直接取消。已进入最终替换阶段的任务禁用取消，成功返回后才显示完成；完成结果未确认时提示检查目标。
- 空文件、源不存在、目标在传输期间变化、权限错误均有结果；失败不清空已有本地目标。传输阶段 60 秒无进度会关闭通道并报告失败，等待同名选择不计入该超时。远端清理另有限时尝试，无法确认清理时错误信息保留临时路径。
- 成功上传仅刷新与上传目标一致的当前目录。修复初始化回调把用户已打开目录覆盖为主目录的问题，单个文件面板始终复用一个浏览客户端。
- 断线停止队列；关闭或重连有未结束任务的会话时提示影响。会话关闭时若正处于最终替换，连接中断可能导致结果未确认，需要核对目标。重连创建新队列，不自动恢复旧任务。

## 验证

- `mvn -B -ntp clean verify`：82 项测试通过，0 失败、0 错误、0 跳过；增加 13 项队列、真实 SFTP 和界面工作流测试。
- 隔离 MINA SSH/SFTP 服务验证上传/下载内容、保留两者、覆盖、跳过、取消、重试、空文件、缺失源、来源/目标路径固定、本地与远端目标修改保护，以及服务端未协商安全替换能力时保留原文件。
- 暂停实际上传的数据回调时，另一个 SFTP 通道仍能列目录；取消后原远端内容保持，再次重试完整成功。取消下载也保留旧的本地目标。正常可清理场景未遗留 `.part`。
- Swing 测试验证排序后取消正确任务、重试新建任务、进度条及中文字体。150% 缩放下传输组件、会话组件和文件上传工作流共 4 项测试通过。
- 最终应用 JAR 优先于测试类的 classpath 运行工作台预览，连接隔离 SSH 服务，经新队列上传 UTF-8 文件并核对远端内容，输出 `WORKBENCH_APPEARANCE_PREVIEW_OK`。预览主窗口未作为人工桌面操作验收。
- 预览文件位于 `target/verification/transfers-*.png`；`workbench-transfers-1.5-sample.png` 展示最终 JAR 的隔离传输，资源栏数值明确为示例指标。既有打包许可证重复及隔离服务关闭警告不影响测试结果。

## 边界

本批只支持普通文件，目录递归、拖入、文件表多选下载、断点续传以及在线编辑保存冲突检测另批处理。在线编辑仍使用原有保存路径，不将这批传输保护描述为编辑器保护。队列仅保存在当前会话内，应用退出或重连不会恢复历史。

属性比较不是跨客户端锁：远端属性仅精确到 SFTP 提供的时间/大小/权限，同长度且相同时间戳的修改可能无法识别，最后检查与替换之间也不存在原子比较条件。连接在发布或清理时中断，可能需要人工核对最终文件和临时文件。尚未实测用户 Debian/OpenSSH、多 GB 文件、实际限速弱网、磁盘写满或异常断电；现有结果不代表这些场景已经验收。

依赖能力核对：[本项目固定 JSch 0.2.20 的 SFTP 实现](https://github.com/mwiede/jsch/blob/jsch-0.2.20/src/main/java/com/jcraft/jsch/ChannelSftp.java)，其协商的 POSIX rename 扩展用于覆盖发布。
