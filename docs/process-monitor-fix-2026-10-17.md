# 进程占用与排序修复（2026-10-17）

原先进程页直接显示 `ps %cpu`，其含义是进程存活期间的平均占用，而不是最近采样间隔的占用。短命的采集 `ps` 因而可能排在第一行并显示 100%。原界面没有启用表头排序，字段全是字符串，且只取 CPU 排名前 150 条，无法可靠查找内存占用最高的进程。

## 当前行为

- 读取两次 `/proc/<pid>/stat`，间隔约 1 秒；使用用户态与内核态 CPU ticks 的差值，除以 `getconf CLK_TCK` 和 `/proc/uptime` 的时间差。单核满载为 100%，多线程进程允许超过 100%。
- 按采集 shell 的 PID 和父子关系排除本轮采集进程，不按进程名包含 `ps` 来过滤。PID 重用通过启动 ticks 区分；新进程或无有效比较样本显示 `—`。
- CPU、内存百分比、RSS 常驻内存、PID、运行时长按数值排序。默认 CPU 降序，点击表头切换升降序，箭头标示方向。搜索和采样更新保留当前排序；选中进程按 PID 与启动 ticks 恢复。
- 获取全部可见进程，取消前 150 条限制；扩展用户名宽度、完整命令参数，新增 RSS（MiB）。运行时长使用 `etimes`，不再把累计 CPU 时间标成运行时间。
- 进程页可见时每 3 秒发起一次采样，支持暂停和手动刷新。隐藏页面停止后续轮询，正在进行的一轮允许完成；连接断开、重连清理及关闭会取消采集并释放 exec 通道。单次命令最长 8 秒，并限制输出体积；失败保留上次结果并显示错误。
- 终止进程读取经过视图排序映射的选中记录，保留明确的 `kill -9` 确认；等待远端返回码，权限不足等失败不会提示成功。测试没有终止任何真实进程。

## 验证与边界

- `mvn -B -ntp verify`：69 项测试通过，无失败、错误或跳过。
- 新增覆盖：近期 CPU 差值、超过 100% 的有效 CPU、PID 重用、计数回退、带空格和括号的进程名、精确排除采集进程、220 条进程不截断、不完整输出拒绝。
- 本机回环 SSH 服务：两次采样通过真实 SSH exec 通道传输，UTF-8 指令、非零返回码和 stderr、超时、主动关闭取消均通过。远端响应由隔离测试服务提供，未执行真实 Linux `/proc` 采集。
- Swing 组件测试：实际表头鼠标事件切换排序，按数值排序、排序/搜索/选择保持、单轮并发限制、隐藏与暂停停止轮询、关闭后拒绝结果，以及深浅主题字体与排序箭头。
- 150% 缩放进程组件测试通过；`target/verification/processes-*.png` 为测试样本的组件绘制结果，非用户服务器数据或原生桌面验收。
- 采集脚本通过 Bash `-n` 语法检查。本机没有可用的 WSL Linux，尚未在用户 Debian 服务器对照实时负载。采集依赖 Linux `/proc`、GNU/procps `ps` 与 `getconf`；不支持的远端会显示错误。
- Maven shade 的重复 LICENSE、NOTICE、module-info 等警告为既有打包警告；本地测试服务关闭时可能记录连接关闭警告。

构建产物：`target/openshell-1.0.0.jar`。重新从 IDE 启动或运行新 JAR 后生效。

## 自动刷新状态可见性补充

开关现在直接显示“自动刷新：开 · 3秒”或“自动刷新：关”，开启时采用绿色粗体文字。连接关闭后显示“自动刷新：已停止”并禁用。底部持续显示开关状态，右侧单独显示“最近更新 HH:mm:ss”，仅在成功获取结果时更新。正在采样或采样失败时也保留开关状态；关闭自动刷新会停止后续轮询，已开始的一轮允许完成。

新增 3 项测试覆盖明确的开关文字和无障碍描述、采样期间切换、关闭后的状态、最近更新时间，以及失败信息和旧数据在切换开关后保留。150% 缩放的进程组件 7 项测试通过，深浅主题生成开关状态预览；预览仍使用测试样本，不代表远端实测。
